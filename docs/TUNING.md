# Tuning RIVEN's moves yourself

This guide lets you adjust the fighter's moves (feel and animation) without
waiting on anyone. You can see the result; that's a huge advantage for this
kind of work.

## How to test a change

1. Open Godot: `C:\GODOT\Godot_v4.7.2-stable_win64.exe`, and open this project
   (select `project.godot`).
2. Press **F5** to run. Move with A/D, jump W, crouch S; combos below.
3. Edit a file, **save** (Ctrl+S), press **F5** again to see the change.

Combos (forward = toward the grey marker):

| Input | Move |
|---|---|
| double-tap forward / back | lunge / back handspring |
| jump + forward / back | front / back flip |
| crouch + forward / back | front / back roll |

## Two kinds of knobs

### 1. Feel — speed, distance, timing (easy, no code)

Each move is a data file in `actors/fighter/moves/` that you edit in the
**Inspector**: click the `.tres` in the FileSystem panel, change values on the
right.

- `speed` — horizontal speed (px/sec)
- `time` — how long a grounded move lasts
- `recovery` — locked time after the move
- `up` — launch height (airborne moves: the flips)
- `spin` — number of full rotations

(These are generated by `tools/make_dash_styles.gd`; editing the `.tres`
directly in the Inspector is simplest.)

### 2. Animation — how the body bends (code, but just numbers)

All poses live in `actors/fighter/fighter_rig.gd`. You're only ever changing
**angles in degrees**. The rig is a chain of "bones" (Node2D nodes); rotating a
bone swings everything attached below it. `0` means "rest pose"; positive and
negative rotate opposite ways. The ground is at `y = 0`; up is negative `y`.

Key places:

- **`_process()`** — the per-move blocks (`if _anim == "handspring"` / `"roll"`
  / `"airflip"`). These set the whole-body `rotation` and `position` (where it
  sits/tumbles), and the pelvis height.
- **`_targets_for()`** — per-move **torso and arm** angles (a dictionary of
  `bone_name: degrees`).
- **`_curl_legs(tf)`** — the **leg** tuck. `tf` is how tucked (0 = straight,
  1 = full). The roll calls `_curl_legs(tf * 0.55)` — lower the `0.55` for a
  looser/bigger tuck, raise it for tighter.

### Bone names

`torso`, `head`, `upper_arm_front/back`, `lower_arm_front/back`,
`upper_leg_front/back`, `lower_leg_front/back`.

## Example: make the roll bigger / looser

In `fighter_rig.gd`, the `"roll"` block:

- `_curl_legs(tf * 0.55)` → lower the `0.55` (e.g. `0.4`) = legs tuck less.
- `bones["pelvis"].position.y = -40.0` → more negative = taller/higher.
- `ROLL_LEN` (near the top) → bigger = taller tumble arc.
- In `_targets_for` → `"roll"` → `torso` angle → smaller = less curl.

Change a number, save, F5, look. Repeat.

## Want to keyframe it visually instead?

The above is "tuning by numbers." The *proper* animation workflow in Godot is
an **AnimationPlayer**: you pose the fighter at keyframes on a timeline and
Godot interpolates between them, and you scrub it live in the editor. That's a
much better fit for nailing acrobatic moves by eye. If you want that, it can be
set up so each move (roll, handspring, flips) becomes an editable animation
track you drag around in the Animation panel.
